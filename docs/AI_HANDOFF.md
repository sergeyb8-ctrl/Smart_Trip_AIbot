# Разработка и настройка AI отдельно

Цель NLP: превратить текст в Draft, не составлять маршрут и не придумывать объекты.

1. Установите requirements-dev.txt в своё виртуальное окружение.
2. Скопируйте .env.example в .env, укажите свой GROQ_API_KEY и при наличии GEMINI_API_KEY.
3. BOT_TOKEN для smarttrip.ai_cli не требуется.
4. Запустите: python -m smarttrip.ai_cli "Петербург на три дня, 10000 рублей, архитектура, без музеев"
5. После изменений выполните: python -m pytest tests/test_ai.py -q

## Поля Draft

destination, days, budget, interests, exclude, pace, start_time.
Все ключи обязательны, неизвестные значения — null.
Дополнительные ключи запрещены.
Категории и ограничения описаны в models.py.
Budget — целый общий бюджет в рублях на одного человека, без жилья и дороги до города.
Модель не должна подставлять «Санкт-Петербург» вместо другого города.
При отсутствии бюджета бот задаёт вопрос.
Перед построением все параметры показываются пользователю.

## Как оценивать качество

- Подготовьте отдельные наборы примеров для настройки инструкций и для проверки.
- Для каждого запроса вручную запишите правильные поля.
- Сравните точность полей и долю полностью корректных ответов.
- Отдельно учитывайте неверный JSON, пропуски и ошибочную подстановку значений.
- Сравните до/после изменения промпта на одном неизменном проверочном наборе.
- Записывайте модель, дату, число примеров и реальные результаты.
- Не выдавайте подставные HTTP-тесты за измерение качества живой LLM.

Стартовые примеры находятся в data/ai_examples.json. Их недостаточно для статистически устойчивых выводов.
Для реальной оценки запустите: python -m smarttrip.evaluate_ai --limit 3
Команда выполняет до трёх реальных разборов, может расходовать квоты и сохраняет результат в runtime/ai_evaluation.json. Параметр --limit допускает от 1 до 12. До и после настройки запускайте одинаковый набор; не используйте весь проверочный набор как примеры в промпте.
Метрика считает долю правильных полей и число полностью правильных разборов. Порядок категорий не влияет на сравнение. Ошибка API считается неуспешным разбором. Отдельно анализируйте поля со значениями: большое число ожидаемых null может завышать общую точность.
Дообучение весов LLM не выполняется. Настройка инструкций и примеров — адаптация использования готовой модели.
Собственная ML-модель рекомендаций может стать отдельным исследованием после появления размеченных данных.
